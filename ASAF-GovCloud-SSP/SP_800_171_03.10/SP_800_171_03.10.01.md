# SP_800_171_03.10.01 - \[Physical Protection\] Physical Access Authorizations

## Control Statement

- \[SR-03.10.01.a\] Develop, approve, and maintain a list of individuals with authorized access to the facility where the system resides.

- \[SR-03.10.01.b\] Issue authorization credentials for facility access.

- \[SR-03.10.01.c\] Review the facility access list [frequency].

- \[SR-03.10.01.d\] Remove individuals from the facility access list when access is no longer required.

## Control Assessment Objective

a list of individuals with authorized access to the facility where the system resides is developed.
a list of individuals with authorized access to the facility where the system resides is approved.
a list of individuals with authorized access to the facility where the system resides is maintained.
the facility access list is reviewed [frequency].
individuals from the facility access list are removed when access is no longer required.
authorization credentials for facility access are issued.

## Control guidance

A facility can include one or more physical locations containing systems or system components that process, store, or transmit CUI. Physical access authorizations apply to employees and visitors. Individuals with permanent physical access authorization credentials are not considered visitors. Authorization credentials include identification badges, identification cards, and smart cards. Organizations determine the strength of the authorization credentials consistent with applicable laws, Executive Orders, directives, regulations, policies, standards, and guidelines. Physical access authorizations may not be necessary to access certain areas within facilities that are designated as publicly accessible.

### This System

**Primary Path (Azure Government — Inherited):**
For ASAF deployments processing CUI in the customer Azure Government tenant, physical access authorizations are fully inherited from Microsoft Azure Government's FedRAMP High Authorization (JAB P-ATO). Azure Government data centers operate under GSA-compliant physical security procedures including: (a) mantrap entry systems with card + PIN + biometric multi-factor access; (b) 24/7 CCTV monitoring with 90-day retention; (c) escort procedures for all visitors; (d) quarterly physical access list reviews. Evidence: Azure Government FedRAMP Security Package, available at marketplace.fedramp.gov (Package ID: FR1703088554). ODP A.03.10.01.ODP.01 value: Quarterly.

**Secondary Path (VPS — SecRed Hostinger, Non-CUI Tier):**
The SecRed VPS (Hostinger) processes no CUI content — it operates as the license authority and telemetry aggregation tier only. Interim measures while Azure Gov path is established: (a) SSH access restricted to named individuals via Dilithium3+Ed25519 hybrid keys (key files in repo: `hostinger_vps_final_dilithium.pub`, `hostinger_vps_final_ed25519.pub`); (b) Hostinger enterprise physical security attestation engagement in progress (POA&M B-3, target Sprint 37); (c) Until formal attestation obtained, this control is `partial` for the VPS tier.

**POA&M Reference:** B-3 (Hostinger physical security attestation — Sprint 37)
