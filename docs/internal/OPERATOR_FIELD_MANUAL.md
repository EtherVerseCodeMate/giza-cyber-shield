## 1. Mission Overview
The **Khepra Protocol** is an Agentic Security Operations Center (ASOC) designed for high-security, air-gapped, and Zero-Trust environments. Unlike traditional SaaS scanners that rely on cloud APIs, Khepra operates entirely locally, ensuring that sensitive client data and Intellectual Property (IP) never leave the engagement perimeter.

### Core Philosophy
*   **Zero-Dependency**: No external API calls (e.g., no Shodan, no OpenAI). All intelligence is generated or ingested locally.
*   **Post-Quantum Cryptography (PQC)**: All audit records are signed with **Dilithium-Mode3** and encrypted with **Kyber-1024** to future-proof against harvest-now-decrypt-later attacks.
*   **Causal Provenance**: Every security finding is cryptographically linked in a Directed Acyclic Graph (DAG), creating an immutable "Trust Constellation."
*   **Agentic Autonomy**: The "SouHimBou" AGI Engine (KASA) actively monitors the perimeter and assists the operator.

## 2. Deployment Instructions

### A. The Toolkit (The Arsenal)
The Khepra binary (`khepra` or `khepra.exe`) is a standalone executable. It has no installation dependencies (no Python, no Node.js required for the core binary).

### B. Deployment Scenarios

#### Scenario 1: The "Listening Post" (Operator Laptop)
This is the standard mode where you run the Agent and the Dashboard to visualize data.
1.  **Build/Download**: Ensure you have the latest `khepra` binary.
2.  **Initialize**:
    ```bash
    ./khepra keygen -tenant "Client-Alpha"
    ```
    This generates your PQC Identity Keys (`id_dilithium` / `id_kyber`) in `~/.ssh/` or `./keys`.
3.  **Start Agent**:
    ```bash
    ./khepra-agent
    ```
    *   **Port**: 45444 (Default)
    *   **Interface**: 127.0.0.1 (Localhost Only for security)
4.  **Launch Dashboard**:
    *   Open `dst/index.html` or run the Next.js frontend if developing.

#### Scenario 2: "Drop & Audit" (Air-Gapped Client Server)
When operating inside a client's secure enclave (e.g., a datcenter or secure VLAN):
1.  **Transfer**: Copy the `khepra` binary via USB or secure SCP.
2.  **Scan**: Use `khepra` to ingest scan artifacts generated by other tools (see Section 3).
3.  **Exfiltrate (Securely)**:
    *   Generate a Risk Report: `khepra audit ingest ...`
    *   Encrypt artifacts for transport:
        ```bash
        ./khepra kuntinkantan ./client_keys/operator_kyber.pub report.json
        ```
    *   The resulting `.khepra` file is safe to transport over untrusted networks.

## 6. Troubleshooting

*   **"Agent Build Failed"**: Ensure `CGO_ENABLED=0` is set. Windows Defender may flag the scanner; add exclusion for `bin/`.
*   **"Stig Library Not Found"**: Ensure `docs/STIG_to_NIST171_Mapping_Ultimate.xlsx` is present in the working directory.
*   **"Ingest Failed"**: Check JSON format. Gitleaks sometimes outputs malformed JSON if interrupted; ensure the file ends with `]`.
